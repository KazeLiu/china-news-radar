# 本地管理后台

后台直接访问 `/admin`，前台导航不提供后台入口。当前本地预览入口为 `http://localhost:3420/admin`；其他环境使用对应站点地址。

- **AI 配置**：开关、兼容 OpenAI 的 Base URL、模型 ID、API Key、每日 UTC 调用额度和额外筛选指令。固定 JSON 协议可展开查看；保存立即生效，后续内容及未完成队列使用新配置。已完成的分析与翻译保持缓存，不因模型或提示词变化重翻。
- **请求详情**：AI 配置下方按时间倒序显示实际请求，每页 10 条。每次重试单独列出，成功、失败、截断和协议无效的请求均保留。点击“查看详情”可查看实际发送的 system/user 消息、请求参数、模型文本、完整响应 JSON 与用量。网页解析辅助也在这里查看，收到的响应在规则校验失败时仍保留；连接失败或超时时显示安全错误原因，没有响应内容时明确说明。列表第一页自动更新，历史页手动刷新；查看不会调用模型。保留暂停、继续和明确启动历史处理的控制。
- **请求明细保存**：输入、输出随实际请求保留 7 天，只向已登录管理员提供，接口禁止缓存；不记录鉴权头或接口密钥，意外回显当前 AI Key 时替换为 `[REDACTED]`。此前没有保存的输入与输出无法补回。未真正发出的任务（例如未配置密钥、额度已用尽）仍在日志统计中查看。升级新增 `AiRequest.inputJson`、`outputJson` 可空字段，使用现有 `node scripts/init-db.cjs` 创建一致性备份并增量升级，预览副本需指定相同 `DATABASE_URL`，然后执行 `pnpm --filter ai-hot-radar-server db:generate`。
- **测试 AI 调用**：AI 配置下方可以输入标题和摘要，用已保存的配置调用一次。可以在自动 AI 关闭时测试连接，但必须已保存密钥；测试与后台分析共用每日额度，失败也计入，不自动重试。模型请求最长等待 120 秒，Next.js 前端代理等待 150 秒；等待时显示已用秒数。面板显示耗时、涉华判断、主题、类型、理由、译文及 JSON。失败结果显示错误类别、具体原因、异常类型、HTTP 状态、已识别的网络错误、提供商请求 ID（如有）和测试时间；不回显可能含密钥的提供商错误正文。主快讯预览只检查内容条件，实际采集还检查来源、发布时间和排除规则。测试不保存新闻、分析缓存或配置。
- **来源配置**：编辑现有来源，或通过“新增来源”选择 RSS、网页、API 或 Telegram。同一来源的地址共用名称、Logo、允许的原文域名和采集间隔。“新增 RSS 地址”可添加地址，至少 1 条、最多 10 条，支持上移、下移和移除。每轮请求所有未处于退避的地址，全局最多 4 个 RSS 请求并发，汇总后按文章 URL 去重。单个地址失败、304 或无内容不会跳过其他地址；全部失败时明确报错。Google News 索引按地址自动识别，RSSHub 也填写完整 RSS 地址，没有独立入口开关。新来源默认暂停，保存后开启。
- **来源信息面板**：编辑区下方显示采集状态，可“测试获取一次”或“删除来源”。测试使用当前未保存的配置，展示尝试地址、原始条数、解析样例和排除原因，不入库、不保存配置、不调用 AI。删除停止采集并移除来源配置，重启不恢复；已有新闻、收藏、时间及针对该来源的规则保留。Telegram 关注关系仍在客户端管理，本站可以暂停或删除接收配置。
- **代理设置**：独立 Tab 保存共享 HTTP(S) 代理地址，各来源通过“使用代理”独立选择，自动采集与当前表单预览使用同一选项。新来源默认直连，旧来源未单独保存时沿用原来的共享网络方式。停用共享代理后全部直连，保留各来源勾选状态；启用时连接失败明确报错，不自动改为直连。内部 RSSHub 地址、采集器访问本站后端的请求始终直连，AI 接口不使用这项代理。
- **来源页布局**：桌面端左侧来源目录与右侧编辑、状态和预览区域分别滚动；切换来源保留目录位置，并把编辑区移回顶部。窄屏按上下顺序阅读。
- **强制视为涉华**：来源配置中的开关默认关闭。开启后，该来源的报道不受 AI 或关键词的涉华判断限制；翻译、分类和评分继续正常处理，新闻类型、出处识别、排除规则、草稿及人工隐藏仍有效。保存开关会重新判定已有新闻的展示资格，不调用模型、不重放通知、不改译文和评分缓存。关闭后恢复原判断。日志保留模型原始判断，并注明来源强制设置。
- **过滤规则**：按来源排除完全相同的标题、包含指定文字的标题/摘要、指定 URL 或目录前缀。文字忽略大小写与多余空格；URL 忽略 www、查询参数和末尾斜线。URL 前缀按目录边界匹配，不使用模糊标题长度判断。可用样例预览未保存的规则，不联网、不调用模型。
- **新闻管理**：默认查询全部新闻。点击列表中的缩略图或标题，在弹窗中查看原文、分析结果、展示预览与手动新闻编辑。没有配图时显示灰色占位。每行右侧的文章、图片按钮控制公开展示，红色及斜杠图标表示已隐藏；隐藏与恢复均需二次确认。后台保留原图预览，公共入口继续遵守隐藏状态；操作不触发 AI。新增手动新闻也在弹窗中录入，仍需保存草稿、主动分析后再发布。
- **批量管理与回收站**：勾选新闻，或“全选当前页”，可批量隐藏/显示文章、隐藏/显示全部图片、删除。操作前显示数量和确认框；翻页、查询或操作完成后清空选择。删除立即在精选、热点、日报条目、关注资讯、Agent、RSS 和通知查询中生效，后台“全部新闻”不包含回收站。切换新闻范围为“回收站”并查询，可查看原文、删除期限及单条或批量恢复。恢复保留原有隐藏、发布状态和译文，不调用 AI、不重放通知。
- **删除保留期**：逻辑删除保留 60 天，服务启动时和此后每小时第 30 分钟清理到期新闻。清理正文、译文、热点、关键词关联、通知、日报中的对应条目和未被其他新闻共用的分析缓存；只保留 URL 防重记录，重新采集或手动录入不会补回。已发出的邮件不会撤回。恢复仅限永久清理前；停止服务期间不清理，重启后补清理。数据库备份按原有机制保留，不随此任务删除。
- **日志统计**：实际模型请求、任务流程和新闻分析结果分开显示。可查看每篇新闻的分类、涉华判断、翻译状态、评分与标签，以及缓存复用和规则兜底。日志保留 7 天，清理不删除新闻、译文、有效缓存或额度；排队与运行中的任务不清理。

规则在 AI 入队前执行，完成结果与兜底展示也遵守规则。默认配置排除 AP 地区索引标题和 `/hub/` 集合页，以及卫报中国栏目入口。默认规则可编辑、停用或移除。Google News 的不透明索引链接仍保持原样，不猜造原文 URL。

例如，“标题完全等于”填 `China - AP News`，只排除这个栏目标题，不排除 `China announces new tariffs`。选择“标题包含”并填 `podcast`，才会排除所有标题中含有这段文字的内容。“作用来源”为空表示全站生效，选定媒体时只检查该媒体；任意一条启用规则命中就排除，匹配内容不是正则表达式。

RSS 使用 `rss-parser` 解析 RSS 2.0、RSS 1.0 与 Atom，再统一读取标题、文章链接、摘要、作者和发布时间。摘要兼容 `description`、Atom `summary`/`content` 和 `content:encoded`；清除 HTML 标签并截断到 1600 字。先核对原文域名、最近 7 天时间范围和排除规则，之后才入库及交给 AI。无 AI 时由涉华关键词和新闻类型规则决定显示；缺少发布时间的文章保留，没有有效链接或标题、正文都为空的条目拒绝。来源原本没有标题时，仅以正文截取作临时兜底，统一 AI 批处理可生成中文标题，成功后显示“AI生成”；原文正文不变，完成的旧缓存不自动重分析。任意非标准标签不会被自动理解，可用测试样例检查是否需要适配。

保存规则后按页重新筛选所有已入库记录，隐藏记录仍保留原文、收藏、首次发现时间和内容更新时间。移除规则时使用已有 AI 缓存或关键词兜底恢复，不自动付费重新分析。采集入口拒绝的新条目不入库；撤销屏蔽后可在下一次 RSS 返回该条目时重新采集。

AI API Key、TG_API_ID、TG_API_HASH 使用隐藏输入框，只能覆盖，不能读回；保存后清空输入框，仅显示是否已配置，留空保持原值。不提供显示明文按钮或 AI 密钥读取接口，也不写入浏览器持久存储。配置保存在服务器 SQLite 的 Setting 表，数据库与备份含密钥，不能公开下载或提交 Git。环境变量继续作为未保存值的部署入口。

“Telegram 账号”保存账号级 API 凭据、注册手机号与采集开关。API ID / Hash 标识应用，手机号指定登录的个人账号，两者不能互相替代。手机号只向已登录管理员显示，API 凭据不能读回。采集器使用 Node.js 与固定版本 teleproto，依赖随根目录 `pnpm install` 一起安装，不需要 Python、venv 或 pip。

Windows 与 Linux 使用同一网页授权流程，不打开输入终端。Windows 一键预览隐藏启动后台采集服务，需要 Node.js 22.15 或更新版本；Linux 先启动独立 `telegram` 服务，见 [部署说明](DEPLOY-RADAR.md#可选-telegram-个人账号)。进入账号配置后：

1. 保存 API ID、API Hash 与 `+国家区号` 加完整手机号，例如中国大陆号码填写 `+86` 后接完整手机号。
2. 后台服务显示“已连接”后点击“开始登录”。页面显示连接、等待验证码和验证结果；优先查看已登录 Telegram 客户端的官方通知，发送方式以页面提示为准。
3. 在本页输入本次验证码。只有 Telegram 明确要求两步验证时才显示密码框，否则直接完成登录。错误验证码或密码可在当前步骤重输；验证码过期则重新开始登录。
4. 登录成功后自动开始采集。暂停只停止采集，不删除 session；服务重启复用有效 session。需要更换登录账号时先保存新手机号，再点击“重新登录”。

手机号持久保存在后台配置中。验证码与两步验证密码只经管理员专用接口临时存在内存，提交后清空输入框，不入库、不回显、不写日志或浏览器持久存储。授权绑定发起的管理员会话、账号与代理配置、采集器实例，十分钟过期；取消、服务重启和配置变更会使待输入内容失效。页面每两秒刷新进度。线上必须使用 HTTPS；不要公开数据库、备份或 session。

“两步验证密码”是 Telegram 账号的云端密码，不是短信验证码、API Hash 或手机锁屏密码。SDK 仅在 Telegram 返回 `SESSION_PASSWORD_NEEDED` 时进入此步骤；留空不能跳过。如果认为自己没有设置，请到官方客户端“设置 → 隐私与安全 → 两步验证”确认账号状态。页面会显示明确的密码要求，不再归类为代理或目录权限错误。

需要代理时，先到“代理设置”保存实际 HTTP(S) 地址并勾选“Telegram 账号使用代理”。登录和采集通过 HTTP CONNECT 隧道连接数据中心，支持代理鉴权。各频道共用一个账号连接，任一 Telegram 来源的代理开关与账号开关同步。后台服务约两秒检查控制配置；更改网络会结束当前授权并重新连接采集，需要在页面重新开始登录。后端与独立采集器须都能访问代理地址，Docker 的回环地址不是宿主电脑。旧 Python 入口不使用此账号代理设置。

Windows 仅在一键预览且后端绑定回环地址时管理本机子进程；Linux 服务由 Compose 管理，网页没有 Docker 权限。预览启动器生成或继承内部通信令牌，自动传给隐藏的后台服务；不写入网页。session 与投递队列保留在 `telegram-collector/state`，不随预览重启清空。只监听后台启用且此账号已订阅的公开频道，每 60 秒刷新匹配；每次连接采集时每频道补抓最近 24 小时最多 25 条，回填不通知。运行中新增频道只刷新监听，不自动补抓历史。

独立采集服务凭 `COLLECTOR_TOKEN` 访问 `/api/news/telegram/control`、`auth/report`、`status` 等私有接口；它们禁止缓存，拒绝网页来源与 Cookie，公网 Caddy 不开放此路径。服务端只允许一个在线采集实例。环境 API 凭据与显式终端入口 `pnpm telegram:login` 保留；使用终端入口前必须停止后台服务，完成后运行 `pnpm telegram:start`。默认无需终端登录。Node.js 登录文件为持久目录中的 `reader.node-session`，可用 `TG_NODE_SESSION` 指定；旧 Telethon session 不覆盖、不自动转换。`outbox.db` 沿用原表并保留未投递消息，不要同时运行两种采集器。

管理员账号在服务器交互终端通过 `pnpm --filter ai-hot-radar-server admin:init` 初始化或重置，预览副本需指定其 `DATABASE_URL`。页面使用账号和密码登录，会话固定 8 小时过期，账号重置后旧会话失效。管理接口统一验证会话与修改请求来源；部署时保留现有 Caddy 全站认证。

验证：后端 news 测试、`scripts/check-ai.cjs` 和 `scripts/check-admin.cjs`；构建后运行 `node scripts/check-ai-timeout.cjs`，用本地 32 秒延迟响应检查真实 SDK 与 Next.js 代理的等待时间；前端构建、所改文件 ESLint、桌面及窄屏预览。集成测试使用隔离 SQLite 与假密钥，不请求付费模型。
