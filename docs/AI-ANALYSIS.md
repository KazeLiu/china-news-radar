# 统一 AI 分析与简体中文翻译

管理员统一提供模型服务，无个人翻译 API 配置。启用的 RSS 与 Telegram 新闻先保存原文，再由后台模型一次返回涉华关系、多个主题、文章类型、原文语言、理由及必要的简体中文译文。未完成分析的候选暂不进入主列表；排队超过 15 秒时规则暂显，分析完成后更新，避免慢模型阻塞快讯。AI 关闭、缺密钥、额度耗尽或失败时使用原有规则。来源身份、日期、空内容与国内来源排除仍先校验，不由模型改写。原始出处未知的频道消息仍只在线索模式显示。

## 开启

打开 `/admin` 的“AI 配置”，填写接口地址、模型和密钥并保存，勾选“启用 AI”开启后台分析。保存后以数据库配置为准，重启保留。下方“测试 AI 调用”可以用自定义标题、摘要检查连接和项目要求的返回结果；每次测试计入每日额度，不保存为新闻或写入分析缓存。

首次未保存后台配置时，也可以在自己的 `server/.env`（本地）或根 `.env`（Docker）设置默认值：

```dotenv
AI_ANALYSIS_ENABLED=true
OPENAI_API_KEY=
OPENAI_BASE_URL=
OPENAI_MODEL=gpt-4o-mini
AI_DAILY_LIMIT=100
```

密钥只在自己的机器填写，不发送到聊天或提交到 Git。`OPENAI_BASE_URL` 可填写兼容 Chat Completions 与 JSON object 输出的可信服务。未指定新开关时兼容旧 `AI_TRANSLATION_ENABLED`，行为为统一分析。模型需要支持 system prompt 和 `response_format: json_object`；不支持或返回无效结构时会回退规则。环境变量默认值在重启后端后生效，已保存的后台配置优先。

## JSON 契约

```json
{
  "version": 2,
  "relation": "related",
  "topics": ["policy", "technology"],
  "type": "report",
  "language": "en",
  "reason": "涉及对中国的芯片出口限制",
  "translation": {
    "title": "简体中文标题",
    "summary": "所提供摘要的简体中文译文"
  },
  "scoring": { "relevance": 9, "novelty": 8, "audience": 8, "quality": 7, "importance": "high", "tags": ["芯片出口"] }
}
```

- `relation`：`related` / `unrelated` / `uncertain`，不表示新闻真实性。
- `topics`：1–6 个不重复主题，首项为主主题；`policy` / `economy` / `diplomacy` / `technology` / `security` / `society`。筛选支持匹配任何一个主题。
- `type`：`breaking` / `report` / `analysis` / `opinion` / `feature` / `sports` / `entertainment` / `other`。主快讯流保留涉华的 breaking/report，其余隐藏但不删除；收藏记录仍可回查。
- `language`：`zh-Hans` / `zh-Hant` / `en` / `other` / `mixed`。简体中文要求 `translation=null`；其他语言要求同一次响应提供标题与摘要的简体中文译文。
- `reason`：不超过 400 字符；字段与枚举严格校验，不接受部分译文、额外字段或 markdown 包裹。
- `scoring`：涉华相关性、新颖性、阅读价值与摘要质量各为 0–10 整数，重要度为 low/medium/high/urgent，标签最多三个。沿用上游权重和来源等级计算质量分与精选阈值；评分不代表新闻真实性。

有原标题时最多提供 600 字符标题和 1600 字符摘要，长内容明确标为截取摘要，不假装读过全文。原文和译文在阅读页可展开对照；模型判断与翻译不会覆盖原始出处、发布时间、首次发现时间或内容更新时间。

### 来源没有标题时

采集适配器保存 `sourceTitlePresent`，Telegram 消息与 X 推文的正文截取标题只作为临时兜底，不算来源原标题。RSS、网页和 API 缺少标题但具有正文时，也可以入库；完整采集正文单独保存，不以生成标题覆盖。

这些记录仍进入同一个批处理，使用第三版协议，增加 `generatedTitle`，只根据提供的正文生成最多 120 字符的简体中文标题。正文最多发送 3000 字符，单条输入 JSON 最多 5500 字符，为 ID 与批次包装预留空间，继续按 20 条、6000 字符双限制拆批。正文少于 20 字符或不足以可靠命名时返回 null；有原标题的新闻继续第二版协议，不生成标题。

有效生成结果保存为 `aiGeneratedTitle` 与 `titleGenerated=true`，API 传递标记，精选、热点、关注、详情及新闻管理在标题旁显示“AI生成”。原始 `title` 与 `body` 不变；失败、未启用或返回 null 时保留兜底且不显示该标记。第一、二版完成缓存继续优先复用，不因增加生成能力重新付费；历史 Telegram 只补原标题缺失标记，不释放历史队列，也无法恢复旧版本未保存的完整正文。

### 省略重复摘要

新闻入库和模型输入共用摘要清理规则：忽略大小写、标点与空白后相同的摘要置空；规范化后至少 40 字符、编辑相似度不低于 97% 的文本也视为标题副本。数字不同则保留，避免省略包含新数据的摘要。这里只比较同一篇新闻的标题和摘要，不合并不同报道。

省略后不保存摘要译文，模型收到空摘要，不能再根据标题补写摘要。正文单独保留，不用摘要清理规则改写正文。来源预览显示同样的摘要清理结果。已有记录在再次采集时按该规则更新，旧的有效分析缓存继续复用，不因清理摘要付费重分析；不批量删除旧缓存。

## 缓存、队列与成本

第二版按完整规范化标题、摘要、目标语言与协议版本计算缓存键；第三版还包括明确的无标题标记和有界正文输入，完全相同输入跨来源共用。URL、发布时间或模型选择变化不自动重做已完成结果；原文分析素材变化才创建新任务。结果、队列、次数及尝试状态存在 SQLite，重启后继续；读取列表、搜索、收藏和刷新都不会调用模型。

新闻每 60 秒合批，每批最多 20 条、输入 JSON 最多约 6,000 字符，分析、翻译和评分共用一次请求。所有任务串行处理，默认请求完成后间隔 500 毫秒，可设为 0；新闻输出预算默认 8,192 tokens，日报与档案最多 4,000。每日 UTC 调用次数在发送请求前以事务预留，新闻、测试、日报、档案及解析辅助共享额度，失败请求也计入。每次请求有 120 秒超时；可重试任务最多三次实际请求，失败按 30/60 秒退避，429 尊重 Retry-After，成功批条目不重试；后台测试与解析辅助只请求一次。失败保留已有有效结果，次数上限不是金额或 token 总量上限。

处理中任务使用 180 秒租约并定期续约。异常退出且租期过期时标为中断，不自动重放可能已收费的请求；管理员查看后决定是否重新触发。已成功入库的结果不会因重启重做。第一版完成缓存继续复用，不因升级自动补评分。新闻编辑后旧任务只更新仍关联旧内容键的条目，避免旧译文覆盖新版。

## 日志

后台“日志统计”区分实际模型请求、任务流程和逐篇新闻处理结果：

- 所有模型用途记录入队、处理、完成、等待重试或失败；实际请求记录模型、尝试次数、耗时、来源、请求 ID 和安全错误。
- 新闻结果记录新闻 ID、短标题、涉华判断、主题、类型、语言、判断理由、翻译状态、摘要是否省略、四维评分、重要度和标签。缓存复用、等待期间的规则暂显、失败兜底单独标记，不计作新的模型请求。
- 日报、关注档案、解析辅助和后台测试分别标注用途，不记录凭据或完整输入正文，也不调用 AI 总结日志。
- 日志、实际请求明细与已完成的任务记录保留 7 天，启动及每日北京时间 03:15 清理。排队、运行、仍被分析队列引用或尚未完成失败处理的任务保留；新闻、译文、有效缓存、来源和每日额度不清理。新增处理明细从上线时开始，不补造历史记录。

用户本轮明确将 Telegram 新闻纳入统一 AI，替代此前排除方案。程序仅处理启用目标频道的新闻，不发送登录信息或私聊。Telegram API 与内容许可对 AI 使用存在限制；本地接口和模拟测试不代表平台许可，真实账号接入前须核对 [API 条款](https://core.telegram.org/api/terms) 与 [内容许可](https://telegram.org/tos/content-licensing)。尚未进行真实账号或真实付费模型验证。

## 本地验证

```powershell
pnpm.cmd --filter ai-hot-radar-server test
pnpm.cmd --filter ai-hot-radar-server build
node scripts/check-ai.cjs
```

`check-ai.cjs` 创建临时隔离 SQLite，使用进程内模拟模型验证真实存取、缓存、TG、中文不重翻与持久额度，不调用任何外部 API，也不修改阅读用数据库。
