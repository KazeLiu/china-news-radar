# 统一 AI 调度

`AiRuntimeService` 是实际模型请求的唯一入口。新闻、日报、关注档案、后台测试，以及显式 legacy 模式中的上游调用均先保存 `AiTask`。后台的任务状态接口只读取数据库。

请求发出前在同一个 SQLite 事务中预留 UTC 每日额度、递增任务实际尝试次数，并创建 `AiRequest`。SDK 不自行重试。全局租期与心跳让多个服务实例也串行处理；完成后遵守保存的间隔，填 0 不增加额外等待。网络故障、429、服务端错误和模型协议异常最多三次实际请求；认证或配置错误直接结束当前任务。后台测试只尝试一次。失败不暂停其他任务。

新闻每六十秒汇总多个来源的候选，按二十条和六千字符两个上限拆批。返回 `results` 数组，每项带完整输入 ID，其余字段遵循第二版分析协议。结果按 ID 保存，拒绝重复、未知或缺失的关联。成功条目在事务中写入缓存并同步热点；未完成条目才能重试。输出截断后缩小剩余批次，每条素材最多被实际请求三次；已完成的一、二版缓存不会因批传输失效。

迁移新增 `NewsAnalysis.historical`，已有记录默认为历史；新内容根据“自动分析新增内容”开关决定是否自动排队。旧代码的启动回填和每秒单条循环已移除。历史处理按钮先提示额度消耗，再由管理员明确启动。队列暂停与新增自动分析分别保存。

服务中断后的运行任务会标记结果未知，不在重启后自动重发可能已被提供商收费的请求。请查看任务 ID 后决定是否手动重试。每日额度耗尽后保留原文和规则展示，不无限重试。新闻任务失败后，下一次一分钟队列维护会解除关联并保留失败原因。

人工生成返回任务 ID，页面逐次查询状态，排队等待不占用一次长 HTTP 请求。日报和档案只有完整校验后才覆盖已有有效结果，浏览页面不会产生请求。
