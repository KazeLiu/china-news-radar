## 4. 独立后台与基本安全

上游参照版本没有独立后台或账号登录页面。本轮沿用当前 `AdminConsole` 配置界面，新增独立后台布局与登录流程，复用现有来源、规则和 AI 配置能力。

采用单管理员账号，不提供公开注册或多角色管理。账号由部署初始化配置设置；密码使用带随机盐的哈希保存，不存储原始密码，不内置默认弱口令。未完成账号初始化时显示配置提示，不开放管理操作。

会话保存在 SQLite，只保存会话令牌哈希及过期时间。浏览器使用 `HttpOnly`、`SameSite` Cookie；服务器 HTTPS 部署使用 `Secure`。会话默认有效期为 8 小时，退出登录后服务端使会话失效，有效会话可在正常重启后继续使用。

登录增加失败次数限制。所有管理 API 统一校验会话，不能只隐藏前端按钮。修改请求同时校验合法来源，区分未登录、登录过期和跨站请求错误；密钥读取接口继续要求鉴权且禁止缓存。应用会话不替代 Telegram 等服务接收入口自己的鉴权。

当前用户报告 `/admin` 出现 401/403，但尚未定位其具体分支；新标签页与配置接口曾正常读取。实施时需要核对实际报错、开发地址与代理转发关系，不假定改成 Cookie 就自动解决现有问题。

当前部署配置包含 Caddy 全站 Basic Auth。本方案默认保留现有部署保护，不自动取消它；网站是否改为公开访问需另行确认。

## 5. 统一来源管理

### 5.1 来源与获取方式

“来源”表示信息来自谁，“获取方式”表示系统怎样取得内容。统一在一个管理页面配置，避免为每种采集方式另建一套后台。

建议获取方式分为 RSS、网页爬虫、API 和 Telegram 接收。X、哔哩哔哩、搜索服务作为预设适配器供选择；它们可以使用对应 API、网页或 RSS 获取内容。Google News RSS 和 RSSHub 输出仍通过 RSS 接入，不额外重复实现采集器。

采集层复用上游已有服务，通过适配接口返回统一的新闻字段：标题、有限摘要、原文链接、发布时间、发布者或作者、来源与平台、图片及必要的采集标识。平台转发与媒体原文分别标注，不能仅凭平台名称把内容标为某家媒体。

本轮仍限定海外涉华报道，哔哩哔哩及其他国内平台保留实现，等待后续内容接入，不默认启用这些采集任务。

### 5.2 通用配置字段

| 字段 | 用途与建议 |
|---|---|
| 来源名称 | 必填，用于后台与前台展示 |
| Logo | 选填，同时支持 URL 和上传；未配置时显示名称缩写 |
| 获取方式 | 必填，选择 RSS、网页、API 或 Telegram，并按需要选择适配器 |
| 采集目标 | 根据方式填写 RSS 地址、网页地址、API 端点、平台账号或搜索词 |
| 采集间隔 | 明确标注单位，与 AI 请求间隔分开；沿用后台存储秒数的方式 |
| 启用状态 | 建议新来源默认暂停，完成配置和预览后手动启用 |
| 来源说明 | 可公开展示，解释来源和内容范围 |
| 备注 | 仅后台可见，记录管理员自己的说明 |

来源 ID 由系统生成，不要求手工输入。移除媒体网站和强制填写的英文名称等重复字段。

高级配置按获取方式展开：网页解析规则、API 鉴权与字段映射、单次采集上限，以及页面未标明时区时的发布时间解释规则。原文域名与发布者识别继续保留，可以由样例辅助填写，再由管理员确认。

RSS 保留有序备用地址、独立条件请求和失败退避。API 鉴权参数与公开信息分开处理，普通来源接口不返回密钥、请求头或私人备注。复用平台服务时传入保存的鉴权配置，不通过临时修改全局环境变量切换密钥。

删除来源后停止采集，保留历史新闻、人工隐藏状态、分析缓存和规则；重启不补回已删除来源。

### 5.3 来源测试区域

来源详情下方保留测试区域，使用当前表单内容执行，不要求先保存。按获取方式展示连接结果、解析结构、提取字段和新闻样例。

测试结果展示标题、摘要、原文链接、发布时间、图片、出处和过滤依据。分别显示连接失败、平台限制、字段缺失、没有新内容与全部被过滤，不能把这些情况统一写成“获取失败”。

默认测试只抓取和解析样例，不入库、不发送通知、不调用 AI。“AI 辅助生成解析规则”和“AI 分析样例”使用独立明确按钮，提示会产生模型请求并计入统一额度；模型测试不自动重试。

## 6. 浏览器网页采集与解析结构

建议新增一个基于 Playwright 独立 Chromium 的网页采集模块。它不连接用户 Chrome，不使用用户浏览器的登录资料，并需要符合项目 Ubuntu ARM64 部署目标。

浏览器负责加载公开页面；程序优先读取文章元数据，再按已保存规则提取列表或文章字段。新闻分析只接收标题、有限摘要及必要出处信息，不发送整页 HTML、脚本、样式、广告或图片。

每个网页来源保存解析结构，例如文章条目、标题、摘要、链接、发布时间和图片的匹配规则。来源详情展示规则、最近检查时间、字段匹配数量和提取预览；规则可以编辑，成功应用后保留上一份有效配置供恢复。

不在每天首次抓取时自动调用 AI，也不自动应用 AI 生成的规则。每次抓取做本地解析检查，正常就继续使用规则。必要字段失配时提示可能存在结构变化；没有新内容或被过滤不触发修复。

管理员点击辅助生成或修复时，只发送经过裁剪的文章元数据和少量内容条目所在的页面片段，并限制输入长度。AI 只返回字段匹配规则，不返回可执行脚本。候选规则先进行本地提取预览，确认后应用，失败保留上一份有效规则。

验证码、登录要求、付费限制和访问拒绝作为独立错误返回，不用 AI 反复分析这些页面。本轮不包含绕过此类限制或每天自动修复规则。

爬虫限定目标地址和域名，禁止访问内网地址，限制重定向、页面超时、翻页次数和单次条数。浏览器资源复用并限制并发，避免每条新闻启动一个浏览器。

通用框架不能保证所有网站均可直接采集。路透及其他目标页面仍需要提供准确 URL、配置解析规则，并由用户确认实际取得的样例。

## 7. 管理员手动隐藏

### 7.1 隐藏与恢复

在 `NewsItem` 上增量保存“手动隐藏文章”和“隐藏全部图片”状态，与 AI 分类和自动过滤状态分开。原标题、摘要、原图信息、收藏和各时间字段不被覆盖或删除。

管理员登录后可以在新闻操作菜单中隐藏或恢复。公开访客没有这些操作权限。后台提供已隐藏新闻列表，支持查看与取消隐藏。

隐藏图片后保留文字、出处和原文链接。隐藏整篇新闻后，所有公共列表、关注相关资讯、Agent 和 RSS 都不返回该报道；已生成日报中的对应条目也隐藏，依赖隐藏报道的概述不能继续展示其内容。

展示条件必须同时满足内容筛选与人工展示状态。采集更新、重新分析、修改过滤规则和重启都不会重置手动隐藏。恢复时复用已保存结果，不自动付费分析，也不重放历史通知。

尚未分析但已手动隐藏的新闻，建议不进入自动付费分析队列。后台查看原始内容与公共展示范围分别处理。

### 7.2 手动添加新闻

后台提供手动添加新闻入口，支持粘贴内容或输入 URL。这里的临时新闻表示手动录入，默认不自动过期或到期下架。

粘贴内容先保存草稿；输入 URL 时复用网页采集能力取得并解析内容，再保存草稿。这两个操作本身不自动调用 AI。管理员点击分析后，走统一调用入口完成分类、翻译和评分，再预览结果、调整展示内容或隐藏全部图片。只有点击发布并满足展示规则后，新闻才对外可见。

手动新闻保存草稿或发布状态，不把它混同于自动过滤状态或人工隐藏状态。采集更新、AI 分析完成和重启都不能把草稿自动发布。发布、隐藏、恢复和预览本身不产生新的模型请求。

未提供原文链接或发布者时，明确标为“管理员录入”，使用站内新闻详情链接，不伪造媒体出处。为此扩展统一内容范围：可展示新闻应有已识别的出处，或明确的管理员录入标记；无出处的普通平台线索仍不自动进入主资讯。相同 URL 的手动录入复用已有新闻，不因粘贴 URL 重复入库。

手动正文可以完整保存，模型仍只接收标题和有限摘要。管理员修改展示文案与修改分析素材分别处理；仅调整展示文案不自动产生付费请求，素材确实改变时由管理员明确重新分析。手动发布纳入同一公共查询、日报素材、关注匹配和通知流程；重复发布、隐藏后恢复不重放通知。

## 8. 统一 AI 配置、调用与批处理

### 8.1 一个请求入口

沿用当前后台 AI 设置页面和 `AiRuntimeService`，统一配置读取、模型请求、队列调度、额度预留、间隔和安全错误处理。新闻分析、日报、关注档案、网页规则辅助和后台测试都通过这个入口。

保留的上游 AI 服务如仍需使用，也通过统一入口请求，不再各自读取密钥并独立建立调用流程。采集器只取得和整理内容，不直接调用模型。

请求实际发出前，在 SQLite 事务中预留额度。每次实际模型请求只计一次，失败尝试也计入请求额度；一批包含多条新闻仍计一次请求。排队期间不提前消耗调用额度。后台显示请求次数与处理条数，避免混淆。

### 8.2 设置与队列控制

保留当前开关、接口地址、模型、密钥、每日额度和额外指令，补充以下控制项。以下默认值已经确认，实际配置可以在后台修改。

| 设置或规则 | 默认值与含义 |
|---|---|
| 请求间隔 | `500` 毫秒，允许 `0`；从上一请求完成到下一请求开始计算 |
| 请求并发 | 初始固定为 1；间隔为 0 也不产生无限并发 |
| 新闻批处理周期 | `60` 秒；多个来源在同一周期刷新时合并待分析内容，再按条数和长度拆批 |
| 每批条数上限 | `20` 条；它是上限，实际还需要按输入长度和输出预算拆批 |
| 自动处理新新闻 | 与 AI 配置可用状态区分，单独控制是否自动提交新内容 |
| 历史积压 | 默认不自动处理，后台显示数量，由管理员明确开始 |

历史中没有有效 AI 完成结果的新闻可以由管理员批量处理；日常刷新后的多来源新内容也批量处理。两者共享请求调度和批次协议，历史处理需要明确启动，普通页面刷新不触发模型。

单条标题和摘要沿用当前长度限制。批次正文输入最多 6,000 字符，新闻输出预算默认 8,192 tokens；网页规则辅助片段最多 12,000 字符。按条数和长度共同拆批，输出截断时缩小剩余批次，不重复提交已成功条目。

提供暂停继续处理的操作。暂停后不发出下一请求，已经发出的请求正常收尾。修改配置、启用 AI、重启和刷新页面都不自动重分析有效旧结果，不自动释放全部历史积压。

### 8.3 批次输入与输出

批次只包含没有有效完成缓存、未被排除或手动隐藏的内容。同内容先合并待分析任务，不因来源不同重复送模型。现有第一版、第二版有效完成缓存继续复用，不因批量传输方式变化失效。

输入提供服务端生成的条目 ID、标题、有限摘要和必要出处。返回外层对象中的 `results` 数组，每项包含输入 ID 和单条分析结果；单条结果继续完成涉华分类、翻译和质量评分。

输出按 ID 校验和关联，不能依赖数组顺序。有效结果逐条保存并同步新闻与热点；重复、未知或缺失 ID 和无效结果明确记录，已有有效结果不被覆盖。已完成的条目不随整批重试再次请求。

日报、关注档案、手动新闻与网页解析结构使用各自输入和输出协议，但共享同一个调用调度。人工触发任务显示排队与处理中状态；模型超时从实际发出请求开始算，队列等待、前端等待与处理租期需要配套调整。

可重试任务首次请求后最多重试 2 次，共最多 3 次实际请求，每次都计入额度并遵守间隔。临时网络故障和限流可以有界重试，配置、认证错误直接停止并提示，不能无条件重复请求。批量输出部分失败时，只处理未完成内容，不让成功记录随整批重新调用。

后台 AI 测试和解析规则辅助仅请求一次。认证、配置错误直接结束当前任务；协议异常最多三次实际请求，失败只停止当前任务，其他任务继续，不因连续失败自动暂停全队列。展示安全原因与请求 ID，不回显提供商错误正文。人工请求返回任务 ID，由页面查询状态。

## 9. 后台日志与统计

后台增加日志入口，提供每日统计汇总和按时间排序的任务详情。摘要由程序计算，不为日志总结额外调用 AI。

| 统计范围 | 展示内容 |
|---|---|
| 抓取任务 | 来源检查次数、成功和失败次数、没有新内容的次数 |
| 新闻处理 | 发现、新增、内容更新、重复和过滤的文章数量 |
| AI 任务 | 实际请求次数、重试次数、成功和失败次数、完成分析的新闻条数、翻译条数 |
| 管理操作 | 手动新闻分析与发布、人工隐藏或恢复、来源预览、解析规则生成或修复 |

分类、翻译和评分在同一个请求内完成时，只统计一次实际模型调用；一个批次的请求次数与它处理的文章数量分别显示。来源预览和其他测试操作与正式采集分别标注，避免把预览算成新增新闻。

时间线记录时间、来源、任务类型、相关接口、结果、耗时以及安全错误原因，支持按日期、来源、任务类型和状态筛选。记录可读的接口类型或去除敏感参数后的地址，不记录密钥、Cookie、鉴权请求头、完整请求正文或提供商错误正文。

日志保留 30 天，清理日志不删除新闻、译文、分析缓存或来源配置。新明细从功能上线时开始记录；旧数据库只有部分累计信息时如实说明，不能反推或编造历史时间线。日期按明确的显示时区统计，AI 每日额度仍按 UTC 计算，并在界面标注区别。

默认通过阅读代码、核对调用关系和查看差异做基本自查，页面和功能由用户在预览环境查看和测试。未经用户后续明确要求，不新增、修改或运行测试，不自动执行构建、React Doctor 或其他测试流程。后台的测试按钮属于用户明确触发的产品操作。

## 13. 数据保护与失败处理

迁移前备份数据库与配置，扩展迁移脚本对本轮新增字段、表和配置版本的检查。禁止使用自动接受数据丢失的参数，原数据库不作为开发实验数据。

新闻原始标题、已取得的摘要、原始链接、出处与各时间字段持久保存。已经完成的中文译文和完整结构化 AI 结果继续保留；日志保留期、来源删除、人工隐藏和批量升级都不清理它们。正文、图片 URL 和获取方式分别保存，实际网页取得多少内容取决于来源，不保存图片文件；手动录入保存完整正文，模型只接收标题与有限摘要。

来源请求失败、解析失败与 AI 失败都保留已有新闻和有效结果。解析候选失败不覆盖当前有效规则；生成失败不覆盖有效日报或关注档案。回退代码时也要考虑新增来源类型及配置版本，不能让旧版本直接读取无法识别的新配置。

公共查询、缓存日报、Agent、RSS、图片和通知需要遵循同一展示范围。隐藏或恢复不会重放历史通知。来源被删除、文章被隐藏或规则调整时，原文、时间和已有分析缓存继续保留。

浏览器爬虫的内存和系统依赖、Ubuntu ARM64 部署、路透具体页面的可访问性仍需要后续确认。保留平台采集代码不等于其当前外部接口已经实测可用。
