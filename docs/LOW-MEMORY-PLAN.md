# 小内存常驻优化

目标：在约 4 GB、与其他服务共享的主机上减少常驻占用和数据增长带来的峰值，保留 RSS、网页、Telegram、AI、热点、精选、日报和关注入口。采集可靠性优先，浏览器只优化不再使用的资源与多余工作，不改指纹、页面加载、状态有效期或所在容器的资源限制。

## 执行顺序

1. 让 AI 任务创建与新闻关联原子提交；准备队列禁止重入，历史和待处理数据分批读取。
2. 热点重要度按数据库分组分页；热度仅分批读取排序字段、保留分页所需候选，最终只读取当前页完整记录。统一列表去掉原文正文，修复精选来源筛选。
3. 启动只修复缺失桥接记录，移除保存 AI 参数后的全库重建；保留规则修改和关键词变化的必要重筛。
4. 主动清理已过期的后端页面快照和站点状态缓存，保留原有 30 分钟有效期；修复代理启动期间已取消任务的资源清理。自动“加载更多”只读稳定 HTML，不生成未使用的截图；管理员预览截图不变。不改浏览器生命周期、并发、页面资源加载或 TLS 路径。
5. 提供独立的非浏览器 Docker 资源覆盖配置和说明，不下调后端与浏览器共同容器的限制；保持原部署入口、持久卷和升级备份。

## 验收与边界

- 本轮只阅读代码、检查调用关系与 Git 差异；用户补充授权修复既有测试夹具，不新增用例、不运行测试，不启动服务、不构建镜像。
- 检查并发入队、已成功缓存、部分失败续批、来源筛选；核对截图的实际消费者、缓存过期与替换、代理取消时序，不恢复空闲关闭或并发限制。
- 不清理新闻、收藏、数据库或现有配置；不变更模型协议和额度语义。
- 既有 AI 测试夹具已同步 Responses 协议与浏览器初始化接口，尚未运行。
- Docker 内存限额是资源边界，不是占用或性能保证。后端沿用基础配置的 4 GiB 上限，它与共享的 3.85 GB 主机容量并不匹配；部署前必须根据真实采集峰值与其他程序占用确认是否有足够资源。
