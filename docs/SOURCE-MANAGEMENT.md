# 统一来源管理

在 `/admin` 的来源配置中选择“新增来源”。名称、Logo、获取方式、目标、采集间隔、公开说明和私人备注在同一表单填写；ID 自动生成，新来源默认暂停。编辑已有来源时沿用原 ID 和全部地址，不自动拆分、新增来源或替换地址。

保存并启用来源后，在右侧“来源状态与预览”点击“立即采集”，无需等待下一次定时检查。按钮只采集当前来源，使用已保存配置，不会把未保存的表单当作正式配置。完成后显示成功或失败，并刷新来源状态；采集中禁用重复操作，其他采集任务正在执行时会明确提示稍后再试。

立即采集复用自动采集的入库、URL 去重、过滤、通知和 AI 队列，AI 是否处理仍由现有设置控制。RSS 条件请求与按地址失败退避继续生效，不绕过限流；X 等平台可能消耗 API 额度。Telegram 继续按频道消息监听，不提供主动拉取。Windows 一键预览会按已保存的来源开关和间隔自动采集；“立即采集”可提前获取当前已启用来源的内容。

RSS 使用“新增 RSS 地址”维护同一来源的多个地址，至少一条、最多十条，共享名称、Logo 和采集间隔。每轮采集会同时请求这些地址，合并去重后处理。所有来源的定时、手动采集和测试预览共用最多四个 RSS 请求并发；仍在退避的地址暂不请求。Google News 索引和内部 RSSHub 也使用这套逻辑。

ETag、Last-Modified 与失败退避按地址独立保存；一个地址返回 304、没有文章或失败，都不阻止其他地址获取。部分失败时保留并合并成功结果，全部失败或退避时明确报告失败。采集状态详情列出每个地址的 HTTP 状态、错误或退避情况。

合并依据规范化的文章 URL，不用标题相似度合并不同报道。同 URL 的本轮结果只交给原入库流程一次；重复抓取仍复用现有分析缓存，不重置收藏、首次发现时间或人工展示状态。不同地址返回同一 URL 时，按表单顺序选取第一份通过基础检查的记录，不按请求完成顺序覆盖。

通用 API 支持 GET、POST、Bearer 或自定义鉴权头，以及纯属性路径字段映射。数组路径留空表示根数组；标题和原文链接必须配置。POST 请求内容是 JSON。后台详情可以读取已保存的私有配置；公开接口与普通配置响应不包含鉴权值、请求内容或私人备注。Logo 上传只接受 PNG、JPEG、WebP，最大 1 MiB；文件保存在数据库旁的 `media` 目录，可通过 `MEDIA_DIR` 指定持久路径。

“X 搜索（TwitterAPI.io，复用上游）”、Bing 和 Hacker News 适配器复用上游服务。预设的请求方法、鉴权头和字段提取固定，表单不显示这些自定义控件；通用 JSON API 仍可自行配置。TwitterAPI.io 使用本来源的 API Key，不接受 X 官方 Bearer Token，也不通过修改环境变量切换。它保留上游的关键词搜索和热度筛选，不能把纯用户名当作账号时间线。哔哩哔哩与搜狗代码保留，本轮不启用国内平台。网页方式的规则与限制保存到同一来源配置，由浏览器采集模块接入。

点击“测试当前表单”只做连接、结构检查和样例提取，不入库、不通知、不调用模型。没有内容、字段缺失、排除规则、出处不明和连接错误分别展示。来源样例可填入 AI 分析面板，只有再点击明确的测试按钮才产生一次请求，使用共享配置和额度。

RSS 测试会读取已有的地址退避状态，但为提取样例不发送条件请求头，也不保存新的 ETag 或 Last-Modified。这样预览过的文章仍会在正式采集时完整读取，不会因为测试推进了水位而漏入库。

API 或网页取得的正文和图片链接可以入库。有原标题时模型接收标题和有限摘要；没有原标题时在同一批次补充受限正文，用于生成标题。无时区的 ISO 时间按来源设置的 IANA 时区解释，默认 UTC；带时区的时间保留其实际时刻。未识别的发布者不会进入公共资讯；在高级配置中补充原文域名前先核对样例。

Telegram 接收器每分钟读取后台启用的公开频道，只有个人账号已经订阅的频道会监听，不自动入群或处理私聊。新增来源不需要固定写入频道常量；每次连接时回填最近 24 小时最多 25 条，标记为历史，避免通知。先在“Telegram 账号”保存手机号与 API 凭据并完成网页授权，使用范围见部署说明。

Telegram 消息中的标题隐藏链接、正文 URL 和网页预览地址会直接提取，无需 AI 识别或增加请求。链接按消息位置排列，去除 Telegram 自身入口、国内链接、内网地址与重复项，最多保存 30 条；Markdown 链接、自动链接与 HTML 锚点也可读取，完整原文仍原样保留。已识别媒体的地址优先作为 `originalUrl`，没有已识别媒体时保留第一条外链，但不伪造媒体名称或放宽公共展示条件。精选、热点与新闻管理显示可点击的“消息外链”，标题继续优先打开原报道；Telegram 消息地址单独保留为转发出处。未知媒体的链接可在新闻管理查看，不会因此进入公共资讯。

外链保存在 `NewsItem.sourceLinks`，增量升级使用现有 `node scripts/init-db.cjs` 先取得一致性备份，再生成 Prisma 客户端并重启后端；不改新闻原文、译文、收藏、首次发现时间和人工隐藏状态，链接变化不使有效分析缓存失效。旧消息未保存的隐藏链接无法从纯文本还原，需要采集器再次投递该消息；不会为了补链接自动翻译历史新闻。

配置版本升级前，初始化脚本会创建 SQLite 一致性备份，保留原始配置与所有新闻、译文及缓存。删除来源只停采并移除配置，新闻和相关规则保留。

## 用 JSON 在测试环境和正式服务器之间迁移来源

进入 `/admin` → **来源配置** → **来源导入与导出**，点击“导出 JSON”下载已保存的来源。可以直接编辑文件，在 `sources` 数组中追加 RSS、网页、API 或 Telegram 条目；也可以点击“下载模板”从最小示例开始。导出不包含右侧表单中尚未保存的内容。

在目标服务器展开“导入 JSON”，选择文件或粘贴内容，点击 **校验并预览**。预览列出新增、更新和需补填鉴权值等事项；确认后一次性合并整批来源，自动备份当前 SQLite。任何条目校验失败都不导入，不会留下半批配置。

- 同 ID 更新原来源，保留来源与新闻的关联；新条目省略 `id` 时自动生成 ID，预览和确认使用同一个 ID。复制条目来新增来源时，要删除旧 `id`，或换成独立 ID，不能在同一文件中重复。
- 不删除文件未列出的来源。显式导入曾删除的 ID 会恢复该来源配置；新闻、译文、分析缓存、收藏与人工展示状态不随来源导入删除。
- **所有导入项（包括更新项）都会暂停**。确认来源正确后再启用，可点击“立即采集”；导入本身不采集、不打开浏览器、不通知、不调用 AI，也不启动历史积压处理。
- 保留多条 RSS 地址、网页解析规则、加载参数、AI 解析提示、采集间隔、排序、时区、强制涉华设置及非 Telegram 来源的 `useProxy` 开关。代理地址在目标服务器另行配置；Telegram 的代理属于账号设置，不随频道导出或导入。修改强制涉华设置会按现有流程更新该来源旧新闻的展示判断，复用完成缓存，不重新调用模型。
- 不导出 API 鉴权值、API 请求正文、私人备注、AI 配置、代理地址、Telegram 账号凭据或登录状态。同 ID 更新保留本站备注；API 的适配器、目标及鉴权方式均未变化时保留本站鉴权值，变化时清空，需在当前服务器重新配置。新服务器不会从 JSON 得到原站的 Key。
- 外部 Logo URL 可迁移，本站上传的 Logo 文件不打包。导出时省略站内 Logo 地址，同 ID 更新保留目标服务器已有 Logo；新服务器需重新上传。JSON 也不包含新闻或译文，它不是数据库备份。
- API POST 请求正文不会导出，避免把其中可能存在的凭据写入文件；同接口更新保留本站正文，跨站需在表单补填，也可在自己的 JSON 中明确填写 `api.body`（有效 JSON 字符串）。
- RSS 地址、目标 URL 或 Logo URL 中的访问参数会原样保留，文件仍应私密保存，不要公开分享带签名或 Token 参数的地址。
- 预览后若后台配置已被修改或后端重启，确认会拒绝并要求重新预览，避免覆盖期间的修改。导入会重置右侧未保存的来源表单。

文件为 UTF-8 JSON，最大 1 MiB；每次 1–100 个来源，合并后总数不超过 100。来源字段沿用普通表单校验。内部 RSSHub 地址必须匹配目标服务器配置的通道；跨环境时自行在 JSON 中改成目标服务器地址。

### 手动添加 RSS 和网页来源

下面是可编辑的格式示例，地址和 CSS 选择器需替换为实际网站内容。`pollSeconds` 单位为秒（60–86400），`sortOrder` 越小越靠前；`publisherHosts` 只填原文发布者域名，不含协议或路径。

```json
{
  "format": "china-radar-sources",
  "version": 1,
  "sources": [
    {
      "name": "示例媒体 RSS",
      "kind": "rss",
      "feedUrls": [
        "https://example.com/china.xml",
        "https://example.com/economy.xml"
      ],
      "publisherHosts": ["example.com"],
      "pollSeconds": 900,
      "sortOrder": 0
    },
    {
      "name": "示例媒体网页",
      "kind": "web",
      "target": "https://example.org/china/",
      "publisherHosts": ["example.org"],
      "pollSeconds": 900,
      "web": {
        "maxPages": 1,
        "rules": {
          "mode": "css",
          "item": "article",
          "title": "h2",
          "link": "a[href]",
          "summary": "p",
          "date": "time",
          "image": "img"
        }
      }
    }
  ]
}
```

接口为 `GET /api/news/admin/sources/export`、`POST /api/news/admin/sources/import/preview` 和 `POST /api/news/admin/sources/import`，均需管理员会话并禁止缓存。预览直接接收上述 JSON；确认接收预览返回的 `document` 与 `revision`。后台日志只记录导入结果及新增、更新数量，不记录完整 JSON、请求正文或鉴权值。

## X 官方账号动态

在现有来源中选择获取方式“API / 平台适配器”、适配器“X 官方 API · 账号动态”。采集目标填写 `USA_China_Talk`、`@USA_China_Talk` 或 `https://x.com/USA_China_Talk`，鉴权栏填写 X 官方开发者控制台的 **Bearer Token**，不填写 Client ID 或 Client Secret。此入口与 TwitterAPI.io 独立，原上游入口不变。

固定使用 GET 和 Authorization Bearer：先通过[官方用户名查询接口](https://docs.x.com/x-api/users/get-user-by-username)取得账号 ID，再通过[账号动态接口](https://docs.x.com/x-api/users/get-posts)读取最近最多 20 条动态，申请发布时间、长文本和媒体字段。每轮最多两次请求，不自动翻页或重试；**测试和正式采集都会实际读取平台 API，可能消耗 X 额度**。目标账号必须公开，开发者应用需有相应读取权限和可用额度。401、402、403、404、429 分别提示鉴权、额度、权限、账号和限流问题，不回显提供商响应正文或密钥。

动态保留正文、图片及发布时间；正文开头仅作临时标题，原始标题标记为缺失，后续仍由现有批量 AI 流程生成标题，不增加单条模型请求。X 原帖域名由预设识别，之后继续经过现有过滤、URL 去重、入库和人工展示状态处理。代理和连接超时沿用来源采集网络配置。

编辑旧来源时不会自动切换适配器或替换来源 ID。切换适配器会清空表单中的鉴权值，防止把一个平台的凭据发往另一个平台；请重新填写对应凭据再测试或保存，同一适配器留空仍保留已保存值。如果曾把官方 Token 填入 TwitterAPI.io 入口并测试，应先在 X 控制台撤销并重新生成。

## 旧来源与后台验收

升级增加 `NewsSource.feedValidators`，不修改来源配置、文章或完成缓存。第一次采集按原 `activeFeedUrl` 将旧 ETag、Last-Modified 对应到原地址，其他地址从完整请求开始。添加、删除或调整地址时保留未移除地址的条件请求与失败状态；修改发布者识别或时区时会重新读取 RSS。

1. 编辑已有 RSS 来源，确认原名称、ID 和地址都还在，用“新增 RSS 地址”加入另一个有效地址。不要另建来源；至少保留一条地址。
2. 点击“测试当前表单”：应列出全部地址，出现两边的新闻样例；两边共有的同 URL 报道只保留一条。测试不会入库或调用 AI。
3. 在未保存的表单里把其中一条改成无效 RSS，再测试：应显示该条失败，另一条的样例仍在。全部地址无效时应明确失败，不能显示“没有内容”的成功结果。
4. 保存有效配置并启用来源，手动采集或等待定时采集。在“来源状态与预览 → 详情”查看每个地址结果。再次采集时，某条返回 304 不能阻止其他地址请求；退避地址会明确标记。
5. 对照同 URL 文章的入库数量、已完成译文、时间和隐藏状态；重复轮次不应重复新增、通知或提交同内容分析。无需为验收开启付费 AI 或历史积压。
