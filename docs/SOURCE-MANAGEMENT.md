# 统一来源管理

在 `/admin` 的来源配置中选择“新增来源”。名称、Logo、获取方式、目标、采集间隔、公开说明和私人备注在同一表单填写；ID 自动生成，新来源默认暂停。编辑已有来源时沿用原 ID 和全部地址，不自动拆分、新增来源或替换地址。

RSS 使用“新增 RSS 地址”维护同一来源的多个地址，至少一条、最多十条，共享名称、Logo 和采集间隔。每轮采集会同时请求这些地址，合并去重后处理。所有来源的定时、手动采集和测试预览共用最多四个 RSS 请求并发；仍在退避的地址暂不请求。Google News 索引和内部 RSSHub 也使用这套逻辑。

ETag、Last-Modified 与失败退避按地址独立保存；一个地址返回 304、没有文章或失败，都不阻止其他地址获取。部分失败时保留并合并成功结果，全部失败或退避时明确报告失败。采集状态详情列出每个地址的 HTTP 状态、错误或退避情况。

合并依据规范化的文章 URL，不用标题相似度合并不同报道。同 URL 的本轮结果只交给原入库流程一次；重复抓取仍复用现有分析缓存，不重置收藏、首次发现时间或人工展示状态。不同地址返回同一 URL 时，按表单顺序选取第一份通过基础检查的记录，不按请求完成顺序覆盖。

通用 API 支持 GET、POST、Bearer 或自定义鉴权头，以及纯属性路径字段映射。数组路径留空表示根数组；标题和原文链接必须配置。POST 请求内容是 JSON。后台详情可以读取已保存的私有配置；公开接口与普通配置响应不包含鉴权值、请求内容或私人备注。Logo 上传只接受 PNG、JPEG、WebP，最大 1 MiB；文件保存在数据库旁的 `media` 目录，可通过 `MEDIA_DIR` 指定持久路径。

X、Bing 和 Hacker News 适配器复用上游服务。X 的密钥从本来源配置传入，不通过修改环境变量切换。哔哩哔哩与搜狗代码保留，本轮不启用国内平台。网页方式的规则与限制保存到同一来源配置，由浏览器采集模块接入。

点击“测试当前表单”只做连接、结构检查和样例提取，不入库、不通知、不调用模型。没有内容、字段缺失、排除规则、出处不明和连接错误分别展示。来源样例可填入 AI 分析面板，只有再点击明确的测试按钮才产生一次请求，使用共享配置和额度。

RSS 测试会读取已有的地址退避状态，但为提取样例不发送条件请求头，也不保存新的 ETag 或 Last-Modified。这样预览过的文章仍会在正式采集时完整读取，不会因为测试推进了水位而漏入库。

API 或网页取得的正文和图片链接可以入库，模型仍只接收标题和有限摘要。无时区的 ISO 时间按来源设置的 IANA 时区解释，默认 UTC；带时区的时间保留其实际时刻。未识别的发布者不会进入公共资讯；在高级配置中补充原文域名前先核对样例。

Telegram 接收器每分钟读取后台启用的公开频道，只有个人账号已经订阅的频道会监听，不自动入群或处理私聊。新增来源不需要固定写入频道常量；首次回填标记为历史，避免通知。仍需要先在自己的终端完成 Telegram 授权与内容使用确认。

配置版本升级前，初始化脚本会创建 SQLite 一致性备份，保留原始配置与所有新闻、译文及缓存。删除来源只停采并移除配置，新闻和相关规则保留。

## 旧来源与后台验收

升级增加 `NewsSource.feedValidators`，不修改来源配置、文章或完成缓存。第一次采集按原 `activeFeedUrl` 将旧 ETag、Last-Modified 对应到原地址，其他地址从完整请求开始。添加、删除或调整地址时保留未移除地址的条件请求与失败状态；修改发布者识别或时区时会重新读取 RSS。

1. 编辑已有 RSS 来源，确认原名称、ID 和地址都还在，用“新增 RSS 地址”加入另一个有效地址。不要另建来源；至少保留一条地址。
2. 点击“测试当前表单”：应列出全部地址，出现两边的新闻样例；两边共有的同 URL 报道只保留一条。测试不会入库或调用 AI。
3. 在未保存的表单里把其中一条改成无效 RSS，再测试：应显示该条失败，另一条的样例仍在。全部地址无效时应明确失败，不能显示“没有内容”的成功结果。
4. 保存有效配置并启用来源，手动采集或等待定时采集。在“来源状态与预览 → 详情”查看每个地址结果。再次采集时，某条返回 304 不能阻止其他地址请求；退避地址会明确标记。
5. 对照同 URL 文章的入库数量、已完成译文、时间和隐藏状态；重复轮次不应重复新增、通知或提交同内容分析。无需为验收开启付费 AI 或历史积压。
