# 浏览器网页采集

网页来源使用独立 Camoufox（Firefox 内核），通过官方 Node/TypeScript SDK 与 Playwright 控制。SDK 的 `os` 参数匹配真实宿主系统：Windows 使用 `windows`，Linux 使用 `linux`，其余设备特征由 SDK 生成，保留默认扩展。不连接现有 Chrome，不加载个人浏览器资料。Windows 默认显示真实浏览器窗口；Linux 默认以 Xvfb 虚拟显示运行，不需要桌面。默认并发一、每页三十秒、五十条、三页；来源高级配置可调整上限。

## 复用来源配置与排序

同一媒体有多个 Tag 列表时，选择已配置的来源，点击编辑区右上角的 **复制来源**，修改名称和目标地址后保存。副本带出当前表单中的 Logo、间隔、解析规则、AI 解析提示及其他来源配置；保存时使用新的来源 ID，默认暂停采集。原来源、已有新闻和采集状态不变，页面快照与上一份有效规则不复制，新的地址需单独检查。

右侧编辑区顶部、“复制来源”左边提供“排序”数字输入框，填写整数后点击 **保存来源配置** 生效。数字越小越靠前；数字相同时，最近编辑的来源在前，编辑较早的在后。保存来源配置、应用或恢复解析规则会记录服务端编辑时间；采集、预览、启停来源不修改这个时间。排序及编辑时间保存在数据库，刷新、重启后保留。

左侧来源列表中的 **已开启 / 已暂停** 是启停按钮，点击即可切换，不需要先选中来源，也不会提交右侧未保存的表单。未完成配置的来源不能启动；已开启的来源即使配置未就绪，也能暂停。

旧来源按现有列表顺序显示初始数字 1、2、3……，不补造历史编辑时间；新来源默认排序为 0。第一次保存排序或来源编辑时间前创建 SQLite 一致性备份，原来源 ID、地址、密钥、排除规则和新闻保留。

网页来源的“保存来源配置”只校验配置格式并写入数据库，不打开浏览器、不依赖页面快照，也不重置下一次采集时间。网页加载和规则提取需要单独点击对应测试按钮；已启用来源仍按原采集计划运行，新来源默认暂停。

## 在浏览器设置中调整等待时间

进入 `/admin?tab=browser` → **浏览器设置**。页面显示配置的内核版本、后端运行平台与显示模式，并提供以下参数：

| 参数 | 默认值 | 调整范围与含义 |
| --- | --- | --- |
| 初始观察时间 | 10 秒 | 0–120 秒。从首次访问开始计时，达到后才尝试读取稳定页面；0 表示不额外等待 |
| 跳转稳定等待 | 3 秒 | 1–30 秒。页面加载完成后，连续这段时间没有新的主页面跳转，才读取 HTML 和截图 |
| 整次页面会话上限 | 120 秒 | 30–300 秒。覆盖观察、正常验证跳转、列表加载、分页与截图；不是每次固定停留时长 |

网页验证刚结束、还在跳转时，先适当增加初始观察时间，例如 20 秒。会话上限必须大于初始观察与稳定等待之和。“恢复默认值”只填写表单，点击保存后生效。设置保存到 SQLite，第一次加入浏览器配置前创建一致性备份；不修改来源 ID、地址、规则或新闻。保存后用于下一次网页测试、自动采集和 URL 导入，正在运行的任务继续使用开始时的参数，不重启浏览器或自动开始采集。

来源中的“每次页面操作超时”仍控制一次导航、按钮或截图操作，默认三十秒。整次页面会话使用独立上限，不再由单页的三十秒操作超时提前结束。导航被下一次正常跳转打断、读取内容时文档切换等情况，只继续观察同一浏览器上下文，不主动重新打开目标网页；截图前重新检查页面版本，防止 HTML 与截图来自两次跳转。主文档解析完成并满足观察和跳转稳定等待后，即可读取完整 HTML，不额外等待广告子页面完成 `window.load`。访问拒绝、安全错误、登录和付费限制直接报告；普通设备检查可在会话上限内自然完成，不自动点击验证码或恢复人工操作流程。

Next.js 代理等待上限为 360 秒，长于最长 300 秒页面会话，留出浏览器初始化和错误返回时间。修改前端代理配置后需要重启前端；预览环境可使用项目根目录的 `重启预览.cmd`。当前页面有新入口而后端尚未更新时，会明确提示重启后端，不使用未经保存的另一套设置。

## 在本机测试路透社

1. 运行 `node scripts/install-camoufox.cjs`，补齐浏览器、官方指纹模型和默认 uBlock Origin 扩展，然后重启后端；使用本机预览脚本时，双击项目根目录的 `重启预览.cmd`。
2. 进入 `/admin` → 来源配置，选择路透社，获取方式改为“网页爬虫”，点击 **填入路透社页面加载示例**。
3. 点击 **测试加载网页**。Windows 会打开独立 Camoufox 窗口，完成后返回页面截图、渲染后的完整 HTML、最终地址和 HTTP 状态，再关闭页面。不需要配置文章解析规则或先保存来源，不入新闻库、不通知、不调用 AI。
4. 可先填写 **AI 解析提示**，例如“顶部头条、Latest News 下方和右侧列表都是新闻，忽略视频推荐”，再点击 **AI 辅助生成候选**。系统从这次加载的 HTML 生成去噪结构样本，只调用一次模型，不重新打开浏览器；提示随来源保存。
5. 点击 **预览候选提取**，在下方查看这份 HTML 提取出的文章列表，包括标题、摘要、链接、图片、时间和基础筛选结果；显示数量受来源的“单次条数上限”限制。
6. 确认文章列表后，点击 **确认应用并保存来源**。系统在同一份 HTML 上校验候选规则，自动填写并保存到“现有自动采集的解析规则”，不再次加载网页、不保存新闻。新来源仍默认暂停，确认后再开启采集。

已有解析规则时，完成第 3 步后，直接点击右侧的 **测试规则**。系统使用当前表单中的“现有自动采集的解析规则”读取同一份完整 HTML，在按钮下方展示新闻列表和字段匹配数量，不需要生成 AI 候选，也不重新打开浏览器、不入库或保存配置。可以修改规则、提取上限、时区或强制涉华设置后再次测试；旧结果会提示重新测试。确认修改有效后，另行点击“保存来源配置”。

示例目标为 `https://www.reuters.com/world/china/`。页面正常加载后，点击完整文字为 `Load more articles` 的按钮，观察 `ul[class*="feed-list-module__list"]` 是否增加子节点；这里只判断内容是否加载，不提取标题、链接、日期或文章数组。按钮消失即结束；默认最多 20 页（含首屏），总时限读取浏览器设置（默认两分钟），渲染后 HTML 最大 3 MB。通过内容增长判断加载是否完成，不把同事当天的 127 篇写成固定完成条件。

返回的 `page.complete` 表示配置的加载步骤是否完成；`stopReason` 为 `loaded`（当前页完成）、`no-more`（加载更多按钮已消失）或 `page-limit`（仍有按钮但达到页数上限）。达到上限会明确展示未完全展开，不宣称整栏已经读完。没有“加载更多”配置时，只加载当前页。

服务端 `WebCrawlerService.loadPage(source)` 返回 `html`、`url`、`status`、`screenshot`、`bytes`、`browserMode`、`loadMoreClicks`、`complete` 和 `stopReason`。管理员预览接口为 `POST /api/news/admin/sources/page`，接收当前来源表单并忽略文章解析规则，另外返回 `snapshotId`、`sourceId` 和快照起止时间；新来源后续使用同一 `sourceId` 保存，不重复创建来源。完整 HTML 在界面中作为文本查看，不在管理页面执行其脚本。

HTML 快照仅在后端内存中保存三十分钟，全进程最多十份，绑定当前管理员登录会话，不把完整 HTML 写入数据库或 AI 任务。重新测试加载网页会使用新快照；修改网址、发布者域名、代理选项、加载更多设置、页数或超时后必须重新加载。修改字段规则后可直接再次测试规则，不需要重新打开网页；已有 AI 候选失效时，使用候选流程才需要重新生成和预览。快照过期、退出后重新登录或后端重启时明确提示重新加载，不自动启动浏览器。

现有规则测试接口为 `POST /api/news/admin/sources/rules/test`，接收 `{ source, snapshotId }`，只在绑定当前管理员会话的快照上执行解析，返回文章样例与结构信息。它与 AI 候选预览复用相同的字段提取和展示规则，但不创建任务或改变候选的预览、应用状态。

自动采集使用已保存的解析规则。配置“加载更多”时，先按相同设置展开列表，再解析渲染后的 HTML；没有该配置时保留原有 CSS 下一页入口。只提取当前列表里的字段和链接，不为每篇报道自动进入详情页。

同事的 WSL 环境直连成功，本机对照则通过已保存的代理和安全 DNS 成功；网络出口及 DNS 不同，不能据此统一强制直连。使用下方“代理设置”和各来源的代理开关明确选择路径，不自动换代理或切换网络。

## 先设置连接，再检查列表结构

进入 `/admin` → **代理设置**，启用共享 HTTP(S) 代理并保存实际地址，再在需要代理的来源中勾选“使用代理”。未勾选的来源直连；停用共享代理时全部直连，无需安装 Clash。本机需要 Clash 时，填写后端电脑上的代理地址，例如 `http://127.0.0.1:7897`；容器中的回环地址不代表宿主电脑。

这项设置用于 RSS、网页、通用 API 与平台适配器；Telegram 账号可单独勾选同一代理用于登录和采集，全部频道共用账号开关。AI 接口、本站 Telegram 接收接口和内部 RSSHub 地址不使用该代理。代理地址在登录后的输入框中明文显示，自动回填已保存的地址，保存后不清空。地址读取接口要求管理员登录并禁止缓存，公共来源响应不包含该地址。首次保存前创建 SQLite 一致性备份，不修改原新闻和译文。

尚未保存此设置的旧安装，继续读取 `SOURCE_PROXY_URL`、`RSS_PROXY_URL`、`HTTPS_PROXY` 或 `https_proxy`；保存后的数据库设置优先，明确选择直连也会覆盖环境变量代理。全新安装未配置代理时默认直连。

本机系统 DNS 返回错误地址时，可以开启“通过代理使用安全 DNS”。该选项经同一代理访问 Cloudflare DoH，连接到校验后的公开 IP，同时保留原站点 Host 和 TLS 域名；默认关闭，查询失败直接报告，不退回另一条 DNS 路径。接口格式见 [Cloudflare 官方说明](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。

在来源选择“网页爬虫”，填公开目标 URL，使用“测试加载网页”检查浏览器访问。现有自动采集的文章页可使用 JSON-LD 或 Open Graph 元数据，列表页仍可配置 CSS 字段规则；该解析入口会等待异步标题和链接，并显示字段匹配数量。页面加载接口不依赖这些字段规则。

来源测试不入库或调用 AI。点击“AI 辅助生成候选”才提交持久任务：从已有快照生成最多 24,000 字符的结构样本，再用保存的配置请求一次模型。系统去掉脚本、样式、表单、导航、弹窗、SVG 等无关内容，清空图片地址但保留图片节点和选择器属性；压缩空白、长文本和重复兄弟结构，保留不同布局及侧栏。仍超出上限时，从页面前、中、后分段取样，不再只发送前十六个 `article`。完整 HTML 和图片地址始终保留在原快照中，预览、自动采集均使用完整内容解析。

AI 解析提示最多 2,000 字符，只指导新闻范围和字段，不改变 JSON 格式或允许执行脚本；模型返回的仍是限定 CSS 规则，不生成文章列表。修改提示或字段规则后需重新生成候选，但不用重新加载网页。`rules/assist`、`rules/preview` 和 `rules/apply` 均使用 `source` 与 `snapshotId`；预览和应用还需候选任务 `taskId`。没有预览或来源及解析配置已经修改时拒绝应用。确认应用候选会复核同一份 HTML，成功后替换规则并保留上一份经过检查的规则。普通保存来源配置和恢复上一份规则不重新抓取；需要检查提取效果时，使用“测试加载网页”和“测试规则”。

如果新闻列表没有显示完整，先看预览中的“匹配数量”和“单次条数上限”。默认最多五十条，最多可配置五百条；达到上限会明确提示。调高上限、修改时区或强制涉华设置后，只需重新预览，无需重新加载网页或再次调用 AI。若匹配数量本身偏少，补充解析提示后重新生成候选，并核对不同新闻区域是否都有对应选择器。

### 网页时间按来源时区补全

完整、有效的发布时间保留原值；只有日期时保留该日期并补上本次采集的时分秒，缺年份时使用采集时间在来源时区中的年份。例如在 `2026-10-14 09:34:56` 采集到 `October 12`，预览为 `2026-10-12 09:34:56`。没有时间、无法可靠识别、日期无效或补全后超出允许的未来时间时，使用本次采集时间，不猜测过去的年份。

预览会标明“按采集时间补全”，预览和保存共用页面加载时刻，不随点击时间变化。同 URL 的旧记录在重新采集到不完整时间时保留已有发布时间（原本为空则用首次发现时间），避免每轮刷新改变排序；后续取得完整、有效的发布时间时仍可更新。此规则用于网页采集，RSS、API 的原有时间解析约定保留，不批量改写旧新闻。

访问限制、验证码、登录、付费内容、加载超时和结构失效分别报告，显示安全错误及可用的 HTTP 状态，不每天自动调用模型修复。通用框架不能保证特定站点可抓取。

验证码判断区分常驻验证组件与当前挑战：空的 CAPTCHA 容器、普通验证脚本或待命 iframe 不单独视为整页拦截；检查标题、验证区域的明确提示和实际挑战 iframe，并排除隐藏区域。普通设备检查可以等待自然跳转；DataDome 可见 iframe 明确显示 `Access is temporarily restricted` 和异常活动提示时，立即报告 `access-denied`，附页面提供的出口 IP 和拦截 ID，停止本次加载，不等到会话超时。正常主文档正在切换时，不使用旧 iframe 判定新页面受限。

### 成功后再次访问，不重新当作全新访客

每次任务仍创建独立的临时上下文，但会在当前 Camoufox 实例内复用本站上一次成功加载取得的 Cookie 和本地存储。只保留目标 origin 的本地存储和适用于目标主机的 Cookie，不读取个人 Chrome 或其他浏览器资料，不向前端返回 Cookie。状态仅在内存保留三十分钟，最多二十个 origin；浏览器断开、后端重启或修改采集网络后清除，明确被拒绝或验证失败时丢弃该站状态。网络修改前启动的任务不能将旧状态重新写回缓存。

DataDome 使用客户端脚本和 Cookie 维护、判断访问会话；丢弃刚成功建立的状态，会让下一次访问再次进入设备检查。保留本站自己的浏览状态可减少重复检查，但是否允许访问仍由站点判断。拒绝页列出的快速点击、脚本问题、网络活动和开发工具是可能原因，不代表这些项目都实际发生。参见 [DataDome JavaScript Tag](https://docs.datadome.co/docs/javascript-tag) 和 [会话 Cookie 说明](https://docs.datadome.co/docs/cookie-session-storage)。

启动时通过官方 SDK 限定真实宿主系统，避免后端重启后随机切换到另一套系统环境。修改启动参数后需要重启后端；下一次加载会创建新浏览器，其浏览状态从空开始，不沿用上一实例的 Cookie。

## 网页测试直接返回结果

填写网页目标后点击“测试加载网页”。后端使用独立 Camoufox 完成普通页面脚本和可选的加载更多操作，直接返回 HTML 和截图；不提取新闻字段，不接入远程人工操作面板。RSS、API、Telegram 的“测试当前表单”保持原行为。

页面的普通脚本可以在时限内完成设备检查和重新导航；若最后仍要求验证码、登录、付费或被拒绝，报告错误原因和可用的 HTTP 状态，不自动操作验证码。远程人工操作的组件与服务代码保留，页面入口不接入，相关 HTTP 接口暂不注册。

请求目标、重定向、页面子请求均检查公开地址；每个浏览器上下文使用独立的回环代理，连接到校验后的 DNS 地址，防止重新解析指向内网。HTTPS 通道仅转发 CONNECT 隧道中的字节，由 Camoufox 自己完成目标网站的 TLS 握手、HTTP 协议和页面加载；HTTP 地址使用已有的限额转发逻辑。浏览器阻止 Service Worker、WebSocket、WebRTC 和弹出新窗口。自动采集的主页面只允许 GET、HEAD、OPTIONS；页面脚本另可发送不超过 64 KiB 的 POST 请求，不自动提交登录表单。内部 RSSHub 仅由明确配置的 RSS 通道直连访问。浏览器子进程不继承后台密钥或来源代理凭据。

## 安装与部署

依赖固定为 `camoufox@0.5.8`、`playwright-core@1.62.0`，浏览器固定为 `156.0.1-beta.36`。官方 SDK 要求 Node.js ≥ 22.15、Playwright < 1.63，不能单独升级 Playwright。配对版本见 [官方 TypeScript 接口](https://github.com/daijro/camoufox/tree/main/typescript)及安装包内的 `browser-pin.json`。

在项目根目录安装依赖后，安装独立浏览器：

```powershell
node scripts/install-camoufox.cjs
```

安装脚本按当前平台下载固定的官方预编译 ZIP，通过官方 SDK 解压到用户缓存目录；不在服务器编译 Firefox，不在采集时临时下载。浏览器包约 1.3 GB，需要能访问 GitHub Releases。Windows 默认通过本机 Clash 的 `http://127.0.0.1:7897` 下载，请先开启 Clash；Linux 和 Docker 未配置代理时保持直连。显式设置的 `HTTPS_PROXY` 或 `https_proxy` 优先，仅影响安装进程，不改变已保存的采集网络设置。正在执行的旧下载需先在其终端按 Ctrl+C 停止，再重新执行安装命令。

| 运行平台 | 固定版本的官方包 | 本项目运行条件 |
| --- | --- | --- |
| Windows x64 | `win.x86_64.zip` | Node.js ≥ 22.15；按上述命令安装，不使用个人 Chrome |
| Linux x86_64 | `lin.x86_64.zip` | glibc 系统、Firefox 共享库、字体与 Xvfb |
| Ubuntu ARM64 | `lin.arm64.zip` | 官方 ARM64 预编译包，无需现场编译；Docker 镜像按 ARM64 构建 |

浏览器包见 [官方固定版本资产](https://github.com/daijro/camoufox/releases/tag/v156.0.1-beta.36)。安装后重启后端，在来源表单点击“测试加载网页”，确认目标环境能够启动浏览器并访问页面。浏览器包安装成功不等于网站允许访问；Linux x86_64 与 Ubuntu ARM64 的容器运行需要在对应部署环境确认。

部署继续使用 `server/Dockerfile.radar` 与 `compose.arm64.yml`。镜像在构建时安装 GTK、DBus、ALSA、X11、NSS、GBM/OpenGL、中文字体、Xvfb、固定 Camoufox 包和官方默认启动资源，以非 root 用户运行。Debian Bookworm 使用 `libasound2`；原生 Ubuntu 24.04 安装依赖时对应包为 `libasound2t64`，其他依赖按发行版确认。Compose 保留共享内存和允许用户命名空间的 `browser-seccomp.json`，不设置禁用沙箱的参数；宿主必须允许非特权用户命名空间。配置来源为 [Playwright 官方 Docker 说明](https://playwright.dev/docs/docker)及 [v1.64.0 通用 seccomp 配置](https://github.com/microsoft/playwright/blob/v1.64.0/utils/docker/seccomp_profile.json)，保留其上游许可。

自动采集、来源预览、URL 提取、解析辅助及保留的浏览器服务均经过同一个官方 SDK 启动入口，不再用 `from_options` 跳过 SDK 初始化。安装命令会准备 SDK 配对的指纹模型和默认 uBlock Origin 扩展；已有浏览器不会重复下载。采集启动前检查资源是否已安装，缺失时报错，不在采集时下载。除匹配宿主系统的 `os` 参数外，不额外指定指纹字段，不启用 GeoIP、额外扩展或验证码解答。

浏览器进程的默认代理不可用，页面上下文单独设置经过公开地址校验和 DNS 固定的回环代理；它根据采集网络配置直连或连接上游代理，不向浏览器传递上游代理凭据。上下文关闭或采集取消时，回环代理及其连接一并关闭。`CAMOUFOX_EXECUTABLE_PATH` 仅供指定已安装的同版本可执行文件，不连接已有浏览器；没有安装或启动失败会明确报错，不回退 Chromium。

需要对照运行模式时，在启动后端前设置 `CAMOUFOX_MODE` 并重启：`headed` 显示窗口、`headless` 无头、`virtual` 使用 Linux Xvfb 虚拟显示。Windows 默认 `headed`，Linux 及 Compose 默认 `virtual`；不自动降级。Linux 原生部署先安装 `xvfb`，具体机制见 [Camoufox 官方虚拟显示说明](https://camoufox.com/python/virtual-display/)。本机成功证据来自有窗口模式，普通无头模式和甲骨文 Linux 部署需在实际环境确认。
