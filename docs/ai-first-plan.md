# 统一 AI 分析与翻译实现计划

## 目标与验收标准

管理员统一配置模型。RSS 与管理员启用的 Telegram 新闻按内容版本分析一次，返回经过校验的 JSON：涉华关系、多个主题、文章类型、原文语言、理由与可选简体中文译文。原文先保存，正常情况下由 AI 决定展示和分类；AI 未配置、预算耗尽或失败时采用本地规则。已是简体中文不重复翻译。阅读与刷新不产生模型调用。

## 范围与约束

本轮实现统一采集处理、持久化共享结果与队列、调用额度、阅读页状态与对照、配置模板和说明。不创建个人翻译配置，不部署服务器，不连接真实账号或使用真实付费密钥。后台登录、访问统计、动态 TG 频道同步属于后续独立功能，不冒充本轮已完成。

用户本轮明确更新此前 Telegram 不进 AI 的选择：启用的频道新闻也统一分析。仅发送所采集的新闻标题与有限摘要，不发送账号凭据、会话或私聊。真实 Telegram 接入仍需遵守其 API/内容使用条款，本地模拟验证不等于真实接入授权或平台许可。

## 文件与任务

- [x] 1. `collector/telegram`：在 AI 候选阶段不被关键词提前丢弃，保留来源与日期校验；先写失败测试。
- [x] 2. `analysis.ts` 与 Prisma：定义、校验结构化结果，按内容缓存；持久化任务、尝试次数与重试/租约，缓存不受阅读、模型切换或元数据时间变化影响。
- [x] 3. `news.service`：原文先存、后台串行调用，AI 结果决定展示和主题；额度先预留，失败和额度耗尽回退规则，编辑期间旧结果不能覆盖新内容。
- [x] 4. 阅读页：多主题、AI/规则状态、类型和理由、原文/译文对照；缓存结果显示，不在浏览器调用模型。
- [x] 5. 配置与项目约定同步；后端测试/构建、前端构建/lint/React Doctor、现有 API 与浏览器验证；保留现场未实测项。
