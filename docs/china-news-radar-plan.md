# 海外涉华快讯站实施计划

> 此文件记录第一版验收与当时决策。后续统一 AI 已覆盖旧的 Telegram 排除/可选翻译方案，见 [统一 AI 计划](ai-first-plan.md)；RSSHub 和当前媒体入口见 [RSSHub 说明](RSSHUB.md)。以最新实现与说明为准。

## 目标与验收标准

面向个人阅读，免费优先，持续获取海外来源的涉华快讯。原文先入库、显示，再进行可选的中文翻译。保留发布、首次发现、更新三个时间和原始出处；不将模型判断标为事实确认。

- 无 AI、X 或 Telegram 凭据也能启动并获取公开 RSS。
- 路透、美联、彭博等免费检索分发入口明确标为 Google News RSS，不冒充通讯社官方 RSS，不承诺比专业电讯更早。
- 同一 URL 去重；精确标题合并展示分发来源，保留各条出处。关键词筛选涉华，过滤常规体育、娱乐和意见文章。
- 采集失败保留已有消息，展示来源状态；超时、并发、HTTP 304 和 429 有处理。
- Telegram 只作为个人阅读的可选接入，使用独立账号；频道消息不送入 AI。未经配置不连接或加入频道，不保存凭据到代码或日志。
- Ubuntu ARM64 Docker 从源码构建，持久化 SQLite，通过带认证的 HTTPS 入口访问。

## 范围与非目标

本轮：个人快讯流、搜索/来源/主题过滤、收藏、来源管理、采集状态、可选 AI 翻译接口、可选 Telegram 采集程序、ARM64 部署配置和说明。

后续：多用户注册、捐赠、付费电讯和 X 接口。保留参考项目的旧模块供参考，默认新闻模式不启动其 AI 行业采集、日报和邮件任务。

## 现状与约束

- 参考仓库 zenitlab/ai-hot-radar，基线 7d3001f；NestJS + Prisma/SQLite + Next.js 16 + React 19。
- 原有扫描先做 AI 分析；夜间每小时采集，不符合快讯目标。
- 依赖锁文件与清单不一致，需要更新一次后冻结安装。
- 服务器：日本、Ubuntu、ARM64、4 核 24GB、已安装 Docker。预定域名 `china-news.951211.xyz`，尚未解析 DNS；用户要求本轮只做本地测试，服务器部署留到后续。
- Telegram 平台内容及 AI 条款需由使用者确认；独立采集账号不保证免封。

## 文件和模块职责

- `server/src/news/`：静态来源目录、筛选与链接规范化、RSS 采集、数据库查询和来源开关、异步 AI 翻译、Telegram 接收接口。
- `server/src/radar.module.ts`：新闻模式的模块入口；旧 `AppModule` 通过显式 legacy 模式保留。
- `server/prisma/schema.prisma`：独立新闻与来源状态模型，不删除原有表。
- `client-next/components/news/`：快讯阅读界面和来源管理，使用现有主题组件。
- `telegram-collector/`：Telethon 个人客户端、交互登录和有限频道监听，凭据由本机/服务器环境配置。
- `compose.arm64.yml`、`Caddyfile.radar`、Dockerfile：ARM64 原生构建、认证入口和持久化；后端端口不公开。
- `docs/DEPLOY-RADAR.md`：Ubuntu Docker 部署、账号登录、可选 AI、备份和验证。

## 设计与失败处理

界面采用安静的新闻阅读布局：纸白/深墨背景、蓝色主操作、清晰日期、文字和来源优先，无虚构新闻或运行统计。系统中文字体配本地 Geist，标题层级和 44px 点击目标；来源状态与错误均用文字解释。

RSS 失败仅更新来源状态，保留消息；无 AI 时保留英文，AI 失败不阻塞快讯；来源未配置显示待接入，不假装采集成功。Telegram 登录只在用户交互终端完成，session 文件加入忽略；生产配置缺少私人认证或内部采集令牌时不启用对应入口。
