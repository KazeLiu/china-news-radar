# Responses 接入与单篇分析

## 本轮范围
- 所有实际模型请求统一改用 Responses API，不回退 Chat Completions；保留现有上游内部调用接口、持久队列、共享额度、成功缓存与历史请求记录。
- AI 配置用当前表单的 Base URL 与 Key 刷新模型列表，未保存也可使用；Key 留空时仅对已保存的同源服务复用后台密钥。不保存草稿配置，不调用模型、不计生成额度。
- 后台新闻列表为尚未完成 AI 分析的新闻提供单篇操作，复用已有分析路径；不自动处理其他失败新闻或历史积压。
- 原始发布者识别不作为已入库新闻的分析前提，单篇、自动新增与历史处理均适用；出处与公开展示仍独立判断。

## 已确认的重试行为
单个任务最多三次实际请求，仅网络、限流、服务端和输出协议等可恢复错误重试。耗尽后任务与未完成分析标为 failed，自动批处理只读取 pending，不会再次自动入队。管理员单篇分析、明确处理历史或素材改变后的新内容可产生新任务；成功缓存继续复用。

CPR 本地接口合同 `D:/code/codex-proxy-rs/docs/api.md` 明确支持 `/v1/responses` 非流式完整 JSON，以及无 `client_version` 参数的 `/v1/models` OpenAI `data` 列表；与当前 SDK 调用形状一致。已核对安装的 OpenAI SDK 4.104.0 对 Responses、输出文本聚合和模型列表的支持，不升级依赖。

## 代码核对结果
- 非测试服务代码只有 `AiRuntimeService` 创建 OpenAI 客户端，实际生成只调用 `responses.create`；新闻、日报、关注档案、解析辅助、后台测试及上游内部接口继续经过现有队列。
- 模型目录新接口受管理员会话和来源校验保护，禁止缓存；提供商认证失败返回本站 502，不误触发管理员退出，不回显 Key 或提供商错误正文。
- 手动分析沿用原路由与服务入口，支持采集新闻；复用活动任务和成功缓存，旧失败任务清理按任务 ID 条件更新，不能覆盖新手动任务；同自动批处理竞争时返回当前实际关联任务。
- 页面同步当前行与编辑预览，只在该新闻状态确为 done 时报告分析成功。历史请求保留原有封套展示，新请求显示 Responses 参数、状态、文本与完整响应。
- 已移除前后端的发布者分析门槛，历史积压统计也包含未识别发布者的记录；来源未确认的采集新闻显示“出处待确认”，分析成功也不会绕过公共查询及通知的出处限制。旧历史与失败状态仍须管理员明确触发，不批量重置。
- 已完成源码、调用关系与差异核对。没有测试、构建、页面渲染或真实 CPR 请求结果。
