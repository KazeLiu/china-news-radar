# Telegram 后台授权重整

## 目标与验收标准
账号配置持久保存手机号与 API 凭据；Windows 与 Linux 使用同一网页授权流程。验证码、两步验证密码仅在本次授权中使用，不入库、不回显、不记日志。成功后复用采集器持久 session；只有 Telegram 返回密码要求时显示密码输入。

## 范围与约束
保留独立 Node.js 采集器、现有持久卷 UID、消息队列与私有令牌接口，不把 Docker 控制权限交给网页。保留独立终端登录命令，但默认网页操作不启动终端。不开启真实账号登录，不运行测试或应用。

## 实现顺序
- [x] 账号保存手机号与采集开关；新增单一采集器租期和限时、仅内存保存的授权交互。
- [x] 采集器成为后台待命进程；通过私有接口接收授权请求与单次输入，授权成功后开始采集，重启复用 session。
- [x] Windows 预览仅隐藏启动同一采集器，不再运行 PowerShell 授权弹窗。
- [x] 页面分离账号保存、开始登录、验证码、条件式密码、采集启停，更新部署及隐私说明。
- [x] 阅读完整调用链与差异，核对取消、配置变更、账号不匹配、过期和重复采集器路径。

## 失败与恢复
授权绑定管理员会话、账号配置版本和采集器实例；取消、超时、配置变更或采集器重启使输入失效。错误验证码与错误密码只重新请求对应输入，不重新发送验证码。Telegram 验证失败不覆盖已有 session。密码为空不能被当成无需两步验证。

## 实现与静态核查记录
- 后端 `telegram-control.service.ts` 管理授权与采集命令，账号配置复用 Setting 记录，不新增数据库结构。私有 POST 控制接口从网站会话校验中分离，仍逐个校验采集令牌并拒绝浏览器请求。
- 采集器拆分为待命入口 `main.cjs`、单次授权 `authorization.cjs`、已有采集逻辑 `collection.cjs`；保持 session 路径、队列表、公开频道范围、历史回填范围与容器 UID。固定 SDK 的实际源码确认只有 `SESSION_PASSWORD_NEEDED` 才请求密码。
- 已阅读调用关系、模块注册、进程入口、Docker 复制规则、前端输入状态及文档，并查看差异。未启动应用、浏览器、真实授权、测试或构建。

## 交付边界
完成代码与调用核查后交付。Linux 容器构建、真实账号授权、重启复用及消息入库仍需要目标环境验收，不能用静态检查代替。
